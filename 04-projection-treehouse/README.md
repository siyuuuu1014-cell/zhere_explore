# Zhere · 开放公域生活原型（正式界面 4 · v16）

> 树林与海岸共存的开放式生活原型。公共世界用于发现、采集与交流，只有个人地块可以开荒、种植、建造与长期改变。

## 启动

> 生产配置模板见 `.env.example`。模板只用于列出变量名，不要把真实 `FEISHU_APP_SECRET` 提交到 Git。

### 服务端方式（必需）

需要 Node.js 24 或更高版本。进入当前目录后运行：

```powershell
npm.cmd start
```

也可以直接运行 `node server/server.mjs`。两个入口现在都会自动读取当前项目根目录的 `.env`；开发热更新使用 `npm.cmd run dev`。

然后访问 `http://127.0.0.1:4175/04-projection-treehouse/`。

没有 `.env` 时默认使用本地开发 Repository；`.env` 中设置 `ZHERE_REPOSITORY=feishu` 后使用飞书。生产环境还必须提供 `server/FEISHU.md` 中列出的飞书环境变量。不能再直接打开 `index.html` 或只使用静态文件服务器，否则账户、世界状态、上传和事件接口不可用。

## 核心机制

- **分区生态**：森林 / 山坡 / 镇中心 / 商业街 / 海岸 / 海面，视频按日期种子 + 推荐分 + 低曝光补偿动态生成
- **随地发布**：背包 `B` 选素材→在脚下发布；纸条 `N` 出现在当前位置
- **跨用户公共世界**：公共素材、公共需求、素材留言和需求回应由服务端统一保存；其他账户刷新或轮询后能在同一地图看到并继续回应
- **永久素材档案**：每日地图只决定素材摆放位置，不再决定素材是否存在；旧需求与回应始终可按素材 ID 打开
- **需求管理**：公告树提供开放需求、我的需求、草稿、已关闭与素材库；需求支持编辑、关闭、重新开放和删除
- **模拟商业需求**：项目/品牌、受众、视频规格、数量、虚拟预算和截止日期均有独立字段，不产生真实交易
- **回应与讨论**：公共需求可跨用户使用视频或文字回应；公共素材留言和层级回复跨账户可见，发布者可以修改或删除自己的内容
- **公共互动**：点赞、共享标签、素材关系、长椅留言、漂流瓶回应和关注写入服务端，同一账户换设备或不同账户刷新后保持一致
- **素材对照**：任意两段公共素材可并排观察，建立“呼应 / 反差 / 顺序 / 暂未命名”关系；关系和说明在公共世界中共享
- **内容治理**：公共素材、需求、留言、回应和关系支持举报；管理员账户拥有真实服务端审核队列，可隐藏违规内容或驳回举报
- **探索手账**：打开过的素材与需求、首次抵达的区域、建立的素材关系会形成可置顶、可回访的个人足迹
- **情境行动盘**：点击角色或按 `Q`，根据附近素材、纸条、资源、设施与个人地块显示当下可做的动作
- **世界图鉴**：顶部“图鉴”或 `?` 随时打开；按核心动作、世界地标、路上发现和个人地块分类，支持搜索、就地说明与“带我去”导航
- **轻量首次引导**：第一次进入只介绍行走、观察、发布、手账与回家五件事，可跳过，之后不会重复打扰
- **服务端视频回放**：上传的视频写入媒体 Repository，详情页通过受 Session 保护的 `/api/media/:id` 播放
- **原地报价**：视频旁 `G`→输入完整报价→系统直接接受并记录模拟成交；成交后显示独立购买回执，并可直接打开背包
- **一人一次、多人独立成交**：每个账户对同一素材只能报价购买一次；不同账户仍可各自成交，公共原素材始终保留
- **基础价格**：同一素材最早 10 笔有效成交价形成均价，数量不足时保持 `null`；阈值由 `BASE_PRICE_TRANSACTION_COUNT` 统一配置
- **副本≠收藏**：收藏是书签，报价成交后获得可摆放的副本，报价不扣除现有灵感币
- **灵感币闭环**：收获作物获得灵感币，建设设施和制作地块物品会同时消耗材料与灵感币；每笔变化进入个人账本。素材报价与需求预算仍是独立研究信号，不影响余额
- **唯一成长**：同一素材的点赞、摆放、报价成交和同一标签只记一次成长；探索新区域、首次打开更多素材、收获与稀有发现会继续展开作物、建筑和小屋能力
- **小窝**：副本摆放/移动/收回/组合，长期保留记录为稳定偏好
- **世界采集**：树林、山坡、城镇和海岸生成不同的再生资源；采集消耗体力，隔天恢复
- **开荒种植**：16 块持久地块依次经历清理、翻土、播种、浇水、生长和收获
- **生活日历**：休息推进日期、恢复体力并推动作物成长；天气与四季改变地块状态
- **设施建造**：工作台、水井、温室和小屋扩建各自解锁制作、批量浇水、稳定生长、体力与副本容量
- **地块制作**：木鸟屋、露天放映台和种子压制把探索资源重新接回视频与个人空间
- **分区放映物**：视频不再是同一种矩形屏幕，会随地貌成为树冠放映架、风筝投影、街边橱窗、贝壳播放器或浮标银幕
- **曝光追踪**：每 8 秒记录 impression_batch（区域/排名/可见时长/距离），区分"不喜欢"与"没看到"
- **素材驱动动态地点**：同标签素材聚集（≥3 段）生成当日主题放映点，开放需求（≥2）生成需求营地，高赞素材旁出现热门标记；位置按日期种子稳定、次日轮换、完全可忽略
- **区域事件牌库**：五个陆地分区各 8 个可重复事件，受季节、天气与玩家行为过滤，每日每区一个标记；回应/忽略均无压力，奖励限于小额资源与叙事
- **可忽略 NPC 故事线**：迟野与南枝两条 4 步记忆型弧线，条件满足才出现，对话引用玩家实际看过的素材，完成给种子等纪念品并可重复回访；NPC 始终明确标记

## 技术说明

- 前端仍为 HTML + CSS + vanilla JS；新增无第三方运行依赖的 Node.js 服务端
- 密码使用 Node.js Argon2id；Session 只通过 HttpOnly、SameSite Cookie 传递
- 世界状态通过 `/api/world-state` 写入 Repository；旧 `localStorage` 数据只做一次迁移，不再作为事实源
- 世界状态写入带 `baseVersion` 乐观并发控制；同一账号在多个页面修改时会提示选择服务端或本页进度，不会静默覆盖
- 公共快照通过 `/api/public/world` 游标分页加载，并在游玩中每 10 秒增量同步；删除和隐藏通过 tombstone 立即从其他账户的地图移除
- 公共写接口带按账户与动作分类的频率限制；素材、需求、留言、回应、点赞、标签和公共关系均即时提交
- 视频通过 `/api/media` 上传，播放接口支持 HTTP Range；旧 IndexedDB 视频仅作为迁移兼容
- 本地 Repository 的视频播放使用文件流；飞书 Repository 会向云空间转发 Range，并在上游忽略 Range 时于服务端流式截取，不把整段视频一次性装入 Node 内存
- 高频事件先进入浏览器内存和 IndexedDB 队列，每 8 秒或满 20 条批量提交；关键事件立即提交
- 服务端按 `event_id` 去重，原始事件与 `derived_signals` 分离
- 研究数据链路：`recommendation_request` 的候选与 `impression_batch` 的每条曝光被服务端投影为逐行事实表（推荐请求/候选/曝光三表），`bid_attempt` / `bid_abandon` / `bid_validation_failed` 单独投影，成交时追加不可变 `base_price_versions` 快照；管理员可用 `/api/admin/research/recommendations.csv`、`/snapshot` 与健康告警字段（含事件增长与曝光覆盖）核对链路
- 上传视频在浏览器端提取时长、宽高与码率并随 multipart 提交；提取失败自动降级为无元数据上传，不阻塞发布
- 单个视频默认上限为 100MB，可通过 `ZHERE_MAX_VIDEO_BYTES` 统一调整；页面从服务端读取实际上限，避免前后端提示不一致
- 飞书存储对不超过 20MB 的文件使用一次上传，超过 20MB 时自动执行准备、分片上传和完成确认
- 静止节能：无按键、无寻路目标且无面板打开时暂停主 requestAnimationFrame 循环，输入或交互立即重启；猫、海鸥、小动物与回声风轮等环境动画改为独立 100ms 低频循环并带 transform 过渡
- `prototype.js` 已进一步拆出 `world-guide.js`（图鉴数据与面板）和 `entry-system.js`（入口、认证表单、法律弹层与注册校验）；`world-foundation.js` 有 Node 契约测试覆盖
- 地图可交互对象统一为「点击 → 寻路走近 → 到达交互半径后执行动作」；视频、需求、地标、资源、漂流瓶、无名处、标签植物、旅人标签与贴纸均复用 `approachWorldInteraction`（E 键观察路径保持不变；灯、猫、小动物、回声风轮等纯娱乐对象仍为直接互动）
- HUD 按 `data-hud-state`（`idle|moving|near|tasking`）三态化：任务面板打开时降噪、移动时折叠对话并压缩资源提示、靠近对象时强化上下文提示；移动端额外压缩固定 HUD 垂直占用，切换带 `.18s` 过渡并尊重 `prefers-reduced-motion`
- 表单草稿通过 `localStorage` 的 `zhere-form-drafts`（JSON 对象，单值上限 2000 字符）自动保存与恢复；素材回应、纸条、举报、角色 bio 与公共素材编辑均接入，成功提交后清除草稿，入口页（登录/注册/找回）带脏数据离开时弹确认层
- 开发环境使用本地文件 Repository；生产环境配置飞书多维表格与云空间 Repository，并在启动及 `/api/health` 时验证全部表格和文件夹权限
- 自动化测试：`node --test server/**/*.test.mjs`
